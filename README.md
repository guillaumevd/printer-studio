# Printer Studio

Version 1.8.1 offers a shared illustrated catalog for DNP, original DI-RS1 and
**DNP VG-RX1HS 2.21**, the custom edition tested with DNP,
DI Support and Citizen CY-02 media on the converted DI-RS1. Printer Studio
detects this edition automatically. Stock DNP images remain separate and retain
their original DNP-only media policy. See [VG-RX1HS details](docs/vg-rx1hs.md).
The DS-RX1 USB/protocol identity stays unchanged for existing drivers and Hot
Folder; external software can continue to show RX1HS.

Printer information and firmware selection share a dashboard that fits the window height.
Activity has its own separate tab.
The log is shown only when selected; its entries can scroll inside that tab.

The application also supports return to original **DI-RS1 01.02** for DI-RS1 printers
previously converted to DNP. Firmware restoration from DNP 2.21 and subsequent
printing were verified on the project's printer on 6 October 2026. Factory DNP
printers are not supported. The bridge verifies the original DI boot/recovery,
firmware checksum and printer identity, then uses the existing DI update transport.
It does not make an automatic firmware backup before transfer. The recovered
package includes only application firmware, excluding donor settings and identity.
Final checks require DI firmware/model, unchanged serial and CWD. Other DNP
source versions remain supported by the guards but untested for restoration on hardware.
Private printer logs are not uploaded by the app.

The recovered DI payload is excluded from Git and must be supplied locally for
this build as `firmware/DI-RS1_0102.bin` with the hash locked in
`app/firmware/di_support.py`; it is included in the local installer and portable
package. The public runtime archive from 1.5.0 does not contain this new payload.

A Windows desktop application for managing DNP firmware on a converted DI Support DI-RS1.
Python backend, local HTML interface, native USB bridge and a dedicated WebView2 window.

## Startup and application updates

The frameless 400 Ã— 500 startup screen checks this repository's latest stable GitHub Release.
It remains visible while the printer and workspace load, then opens the app maximized, keeping the title bar and Windows taskbar visible.
Choose **Install update** to download, verify and install a newer application version,
or **Continue to app** to skip it. Network errors do not prevent offline use.
The installer runs after Printer Studio exits and restarts the updated application.
Application updates never flash the printer. The splash is shown before USB detection.

Release tags use `vMAJOR.MINOR.PATCH`. Each release must contain the matching x64
installer and `update-manifest.json` generated by the build. Drafts and prereleases
are ignored. Downloads are size-limited and checked against the manifest's SHA-256;
asset URLs must belong to this repository and release. No GitHub credentials are
stored in the application. The installer is not code-signed.

## Printer firmware

Connect one compatible printer, refresh detection, verify its identity, select a
firmware version and review the proposed route before confirming.
Keep the printer powered on and USB connected until its version and serial number
are verified after restart. Do not use other printer utilities during a transfer.

Bundled catalog: DNP **02.04, 02.07, 02.10, 02.21**. Upgrades follow successive
versions; downgrades send the selected image directly. Same-version transfers are
blocked. A separate action restores original DI-RS1 01.02 on compatible converted DI printers.

The upward sequence and the 02.21 â†’ 02.10 downgrade have been verified on the
project's converted printer. Other downward transitions remain unverified on
hardware. A successful version check does not replace a test print.

This tool expects the retained **DI-RS1_RW_1.00** bootloader. It is not a general
updater for original DNP printers or other printer models. Payloads are locked by
SHA-256 in Python and C#. Only the outer wrapper is adapted to the DI bootloader;
DNP application code is unchanged. No CWD, RFID, calibration, serial-number or
counter write commands are imported by the bridge.

## Data and recovery

Installed and portable editions store logs in `%LOCALAPPDATA%/Printer Studio/logs`.
They survive application upgrades and uninstall. Source mode keeps logs locally.
New instances share a per-user hardware lock across install locations. Close old
instances before launching a newer build. Setup does not force-close the app.

An interrupted operation leaves `active.json` and blocks further firmware writes.
Inspect the log and the printer in read-only mode first. Archive the marker only
once normal firmware and the expected identity have been confirmed. An unexpected
bootloader state requires diagnosis; no automatic retry is performed.

Update downloads and installer logs are stored under the application's `updates`
directory. Printer data and logs are not published to GitHub.

## Source development

Use 64-bit Python 3.10+ on Windows and install `requirements.txt`.
Run `packaging/prepare.ps1` to retrieve the checksum-verified runtime assets and
Microsoft-signed WebView2 bootstrapper. Firmware images and the vendor DLL are
binary release resources; they are not part of the source tree. Their original
vendor rights remain applicable.

Run `native/build.ps1` to build the C# bridge and its checksum manifest, then:

```powershell
python run.py
python run.py --demo --port 8766
python -m unittest discover -s tests -v
python -m tests.desktop_smoke
```

`--browser` uses a browser; `--no-browser` runs the loopback server only. Source
mode shows the splash but does not install release binaries over the source tree.
The server listens on 127.0.0.1 and protects mutations with a session token and
host/origin checks. Demo mode never accesses USB.

## Build and publish

Install Inno Setup 6, run `packaging/prepare.ps1`, then:

```powershell
./packaging/build.ps1 -InnoCompiler 'C:/Program Files (x86)/Inno Setup 6/ISCC.exe'
```

The build uses a dedicated virtual environment and pinned build dependencies.
Change `VERSION` in `app/core/paths.py` for a release. Output in `release/` includes
an installer, portable ZIP, integrity manifest and SHA-256 list. Publish the
matching source tag, installer and manifest together as a GitHub Release.
Create a draft, upload all assets, then publish it so clients see a complete release.
Keep `v1.4.0/runtime-assets.zip` available for source builds.

To verify a packaged application without touching USB:

```powershell
& './Printer Studio.exe' --self-test 'C:/Temp/printer-studio-test.json'
```

The integration harness `--update-test <report.json>` starts a simulated device,
exercises the actual splash install button against GitHub, and runs the packaged
self-test after the updated installer completes. Only use it when a newer stable
release exists. It installs an actual application update, but sends no USB commands.

## Components

- `app/core/`: shared bundle paths and application version.
- `app/firmware/`: verified image catalog and transition planning.
- `app/printer/`: serialized operations, logs and native/demo transports.
- `app/desktop/`: Windows workspace, splash and GitHub application updates.
- `app/web/`: loopback HTTP server.
- `app/validation/`: complete bundle integrity checks and isolated desktop tests.
- `native/transport/`, `native/protocol/`, `native/firmware/`: USB ABI, printer queries and guarded firmware transfer.
- `web/scripts/components/`: printer, firmware and activity views.
- `web/`: HTML, CSS and printer artwork.
- `packaging/`: PyInstaller specification, Inno Setup installer and build tools.
- `tests/`: firmware orchestration, HTTP security, updater and desktop tests.

The startup flow was inspired by [VG-Timing](https://github.com/guillaumevd/vgtiming).

## Distribution integrity

Both distributions contain a `bundle-manifest.json` covering every application file. Verify an extracted or installed package without accessing USB:

```powershell
& './Printer Studio.exe' --verify-bundle 'C:/Temp/bundle-report.json'
```

The desktop self-test also verifies the bundle, displays an unconverted simulated DI-RS1 01.02, runs the four-step conversion and verifies a DNP downgrade. Native protocol tests compile the actual bridge workflow against a simulated USB API; no vendor DLL is loaded by those tests.
